1 anau cœur de la migration des données vers AWS

L’enjeu

Migrer les données de réservation vers AWS, et garantir qu’un site visité dans le monde entier répond juste, même sous de très gros volumes de connexion.

Trois terrains

Data quality sur AWS

Sécuriser l’intégrité du patrimoine de données migré : conformité des tables et des datasets sur AWS.

Tests front-end

Le site grand public de réservation d’hôtels et de produits dérivés : un parcours sans faille malgré des volumes de connexion massifs.

Tests back-end sur les API

La validation des flux de réservation côté API, d’abord à la main sur Postman, puis automatisée.

La matrice de prédiction

Côté back-end, les data scientists ont généré par machine learning un CSV qui prévoit la réponse de l’API pour chaque combinaison de réservation.

Les inputsDates, parc, hôtel, chambre, nombre de personnes, pays et langue du client
Envoi de la requête
L’APILa réponse réelle
Comparaison avec la matrice
Les outputsDisponibilité des chambres, produits à afficher

Le déclic

Sur Postman, un test consistait à envoyer les inputs dans une requête, puis à vérifier que les outputs étaient les bons pour un scénario donné. Impossible de passer à l’échelle.

  1. Chaque ligne du CSV contient les inputs et les outputs attendus du même scénario.
  2. Mon script Python envoie les inputs à l’API.
  3. Il compare la réponse de l’API aux outputs de la matrice.
  4. Il boucle sur l’ensemble du fichier, scénario après scénario.

J’ai proposé et développé ce framework sur mesure : il a permis de valider la robustesse des API face aux contraintes de charge.
